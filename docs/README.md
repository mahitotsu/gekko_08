# 文書の案内

このリポジトリの文書を、目的ごとにどの順で読めばよいかを示す。

## 読む順

1. **[README](../README.md)**：何ができるか、何を守れて何を守れないか、デプロイしてデモを試す手順。
2. **[設計ガイド](guide.md)**：仕組みと用語、各判断の根拠、自分のシステムへの当てはめ方、この構成が守らないもの、運用（トレースとログの見方、
   レイテンシの実測、規模の上限）。参照実装を自分のシステムに持ち込むときは、ここを読めば足りる。
3. 必要に応じて、次を読む。
   - なぜ作ったのか、既存の解決策とどう違うのか：[PRFAQ](prfaq/aws-authorization-context-propagation.md)（実装の前に書いた文書）
   - 参照実装が満たすべきこと：[要件定義](requirements.md)
   - 構成の詳細（IAMのポリシー、共通部品の動き、CDKの構成、テストと要件の対応）：[設計書](design/architecture.md)
   - 個々の判断の経緯と、採用しなかった選択肢：[ADRの索引](adr/README.md)
   - 判断の根拠になった実機での観測：検証記録（`experiments/*/RESULTS.md`。各ADRと設計ガイドからリンクしている）

## 文書の関係

文書は、PRFAQ → 要件定義 → ADR → 設計書 → 設計ガイド・READMEの順に作っている。下流の文書は上流の文書を元にし、検証記録はどの文書からも根拠として引く。
同じ事実が複数の文書にある場合、現在の構成は設計書が、デモの手順はREADMEが、実測値と運用の方法は設計ガイドが正しい。

文書を書く側の運用ルールは、[CLAUDE.md](../CLAUDE.md)にある。
