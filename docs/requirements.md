# 要件定義

参照実装を設計する前提となる要件をまとめる。

関連文書：[PRFAQ](prfaq/aws-authorization-context-propagation.md)、[多段伝播のADR](adr/20260930064314-multi-hop-authorization-context-propagation.md)、
[入口のADR](adr/20260930083437-entry-via-bff.md)、
[委任の範囲と業務的なアクセス権のADR](adr/20260930150529-delegation-scope-and-entitlements.md)

## 目的と対象

- AWS上でマイクロサービスを実装するエンジニアに向けて、Authorization ContextとWorkload Identityを分離し、
  「誰の権限で処理するのか」を多段呼び出しの奥まで届ける仕組みの参照実装（OSSのCDK構成と設計ガイド）を提供する。
- 事業化はしない。サポートやSLAは提供しない。

## 機能要件

| ID | 要件 |
|---|---|
| FR-1 | 各ホップは、受け取ったリクエストについて次の4つを確かめられる。(a) 誰の代理か（ユーザーの識別子）、(b) どのサービスから来たか、(c) 自分宛てか、(d) 委任の範囲（この取引の目的と、呼び出し元に許された操作）。OAuth Token Exchangeと同等のことを実現する |
| FR-2 | 認可判定は、各ホップのアプリが、検証済みの委任の範囲と、権威あるデータ源から得た業務的なアクセス権の両方を使って行う。ヘッダー・引数・自然言語による自己申告は使わない |
| FR-3 | ユーザーの識別子と取引の目的は入口で確定し、途中のホップ（AIエージェントを含む）は変更も拡大もできない。業務的なアクセス権は権威あるデータ源から得て、途中のホップは変更できない |
| FR-4 | 途中のホップを飛ばして、その先のホップを呼ぶことはできない |
| FR-5 | ブラウザなどのパブリッククライアントには、認証情報（IdPのトークン、AWSの認証情報）を持たせない |
| FR-6 | 各ホップの処理を、元のユーザーとリクエストに結びつけて追跡できる |
| FR-7 | デモとして、同期のマイクロサービスの多段呼び出しに加えて、AIエージェント→MCPサーバー→内部サービスのシナリオを含める。プロンプトインジェクションで誘導されたエージェントの要求が拒否されること、取引の目的によって許す範囲が変わること、業務的なアクセス権の変更が反映されることを示す |
| FR-8 | 業務的なアクセス権の変更（異動など）は、次のリクエストから反映される |

## 非機能要件

| ID | 要件 |
|---|---|
| NFR-1 | サーバーレスとマネージドサービスを最大限に使い、コストと運用負荷を下げる |
| NFR-2 | 認可サーバー、SPIRE、サイドカーなどの常駐コンポーネントを持たない |
| NFR-3 | レイテンシの目標値は置かない。ホップごとの追加時間を実測して公開する |
| NFR-4 | 利用者が`cdk deploy`で自分のAWSアカウントに再現できる |

## セキュリティ要件

| ID | 要件 |
|---|---|
| SR-1 | ホップ間で受け渡す認証情報が漏れても、それだけではどのホップも呼べない |
| SR-2 | 同じアカウント内の他の主体（広い権限を持つものを含む）が、許可されていないホップを呼べない |
| SR-3 | 認証情報を、ログ・トレース・エージェントのLLMのコンテキストに入れない |

## 前提と範囲

| 項目 | 初版の範囲 |
|---|---|
| 呼び出し方式 | 同期呼び出しだけ |
| 処理時間 | 1回のリクエストの処理は、各ホップで15分以内に収まる。長い対話は複数のリクエストとして扱う |
| アカウント | 単一のAWSアカウント |
| 連携先 | AWS内部のホップ間だけ。AWSの外のサービスにユーザーの証明を渡すことは扱わない |

## 将来の拡張（初版では扱わない）

- 非同期処理（SQS・EventBridgeなど）を挟む呼び出し
- 複数のAWSアカウントにまたがる構成
- AWSの外のサービスへのユーザーの証明の受け渡し（AgentCore Identityなど既存の手段との使い分けを含む）
- 利用者のサービスの実装言語を問わず、共通部品の機能を使えるようにする
- API Gateway（REST API）を経由してホップを呼べるようにする（WAF、スロットリング、プライベートAPIを使う既存のシステムへの当てはめ）

## スコープ外

- 業務RBACの持たせ方の一般論（参照実装では1つの例を示すにとどめる）
- ユーザーの権限でAWSリソースに直接アクセスすること
